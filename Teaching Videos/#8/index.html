01 / THE PROBLEM

Why doesn't height: auto animate?

CSS normally needs two numeric values to animate between. But auto isn't a number. It tells the browser to figure out the size based on the content.

THE OLD PROBLEM 
.panel {
  height: 0;
  transition: height 0.5s ease;
}

.panel.open {
  height: auto; /* Jumps instantly! */
}

Frequently Asked Questions

Interactive
What is interpolate-size? +
It's a CSS property that allows the browser to smoothly animate between numeric sizes and intrinsic sizes like auto.
Why would I use it? +
It makes expanding content feel more natural. It's useful for FAQs, expandable cards, menus, and other sections that change size.
Do I need JavaScript? +
Not for the basic accordion! HTML details and summary elements already handle opening and closing. CSS handles the animation.
Does it work in every browser? +
Browser support varies. In browsers without the required animation features, the accordion can still open and close normally.

03 / THE COMPARISON

Old way vs. new way.

The max-height trick uses an arbitrary maximum. The newer approach can transition toward the content's actual height.

OLD METHOD

Using max-height

This can look uneven because the animation continues after the content reaches its size.

This content has a fairly short height. But the CSS is transitioning toward a much larger max-height value. 
max-height: 0;
max-height: 500px;
NEW METHOD

Using interpolate-size

This allows a transition toward auto, matching the content's actual height.

This content expands to its natural height instead of an arbitrary maximum. 
height: 0;
height: auto;
04 / THE TAKEAWAY

Small property. Big difference.

With interpolate-size, CSS can create smoother expanding layouts without calculating pixel heights in JavaScript.

:root { interpolate-size: allow-keywords; }
